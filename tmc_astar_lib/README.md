* A*探索ライブラリ

インターフェース
-------------------------------
A*探索アルゴリズムの実行は、AstarExecuterクラスのExecuteAstarインターフェースを使用する.  
以下にその概要を示す.  

* ExecuteAstarインターフェース  
探索対象の地図・スタート・ゴール・最大コストを入力すると、経路が出力される.  

* 探索対象の地図  
探索対象の地図には、IMapを継承したオブジェクトを指定する.  
探索対象の地図をどう実装するかによって、探索の特性をユーザが定義することが出来る.  
本パッケージでは、一つの継承例としてLayeredCostMapクラスを定義している.  
LayeredCostMapは、静的なグリッドマップと動的なグリッドマップを重ね合わせた地図.  

* スタート・ゴール  
スタート・ゴールは一意に指定することも、複数指定することも可能.  
複数指定する場合は、それぞれのスタート・ゴールにコストを付与し、重み付けすることが出来る.  
重み付けされたコストを加味した上で最適解となるスタート・ゴールを結ぶ経路を出力する.  

* 最大コスト  
指定した最大コストを超えてしまった場合は探索失敗とする.  
何がどれだけの探索コストになるかは探索対象地図の設計に依存する.  

* 出力経路  
tmc_pose_2d::Pose2dの配列を出力する.  
tmc_pose_2d::Pose2dは座標と姿勢を表現するが、姿勢についても出力するかはIMapの実装次第.  
前述のLayeredCostMapを使用した場合、座標だけが格納され、姿勢情報は全て0度が出力されるので注意.  
※グリッド単位で計画した経路は平滑化され使用されることがほとんどであり、姿勢を付与しても無駄になる為  


注意事項
-------------------------------
* 探索処理速度について  
A*探索ロジックは、スタートからゴールまで最適解でたどり着くまで、地図を繰り返し探索する.  
条件によっては、繰り返しの回数は膨大になる.  
そのため、少しの変更・少しの処理コストが探索処理速度に及ぼす影響が大きい.  
変更を加える場合や、IMapを継承したクラスを新たに定義する場合には注意が必要.  


* 探索処理速度の自動テストについて  
探索処理速度の比較を行うための自動テストを定義している.(test/astar_executer-test.cpp PerformanceTest)  
変更を加える場合は、変更前と変更後でこれを実施し結果を比較することで、性能の劣化が発生していないか検証できる.  
ただし、実行環境の性能により結果が毎回変わり、特にJenkins環境でばらつきが大きく正しく合否判定が出来ないため、普段はテストを無効化している
